# Подключение desktop

После «Начать чат» выберите свою роль:

- **Создать приглашение** — приложение создаёт QR и код приглашения. Передайте любой
  из этих вариантов собеседнику, затем вставьте полученный от него ответ.
- **Принять приглашение** — вставьте полученный код или загрузите изображение QR.
  Приложение создаст ответ; отправьте его тому, кто вас пригласил.

После обмена сравните код сверки на обоих устройствах и подтвердите совпадение.
Если подтвердил только один участник, приложение ждёт второго.

QR можно сохранить в PNG. При импорте поддерживаются PNG, JPEG и WEBP до 5 MiB;
изображения больше 16 мегапикселей отвергаются. Камера пока не подключена.
Ошибки создания или приёма показаны рядом с действием; код можно исправить и повторить.
При редактировании приглашения прежний ответ скрывается, чтобы не отправить его по ошибке.

Короткие ссылки используют отдельный сервис `ssc-connect`. Настройка и сценарий
описаны ниже. Регистрации и общего кода доступа нет.

Для проверки экранов используйте `npm test`. Нативный сценарий двух окон описан в
[desktop protocol](DESKTOP_PROTOCOL.md#validation) и выполняется скриптом
`scripts/native-smoke.mjs`.

## Короткая ссылка

На экране подключения выберите «По короткой ссылке».
Создатель нажимает «Создать ссылку» и передаёт её собеседнику. Гость вставляет ссылку
и нажимает «Подключиться по ссылке». Ответ передаётся помощнику автоматически;
копировать его обратно не нужно. Сверка SAS остаётся обязательной для обеих сторон.

Настройка TTL применяется к серверному приглашению. При временной ошибке кнопка
«Повторить подключение» продолжает прежнюю операцию: сохраняются ключ идемпотентности,
offer и подготовленный answer. Новая ссылка создаётся только отдельным действием.
Отмена прекращает локальную операцию и пытается удалить известную серверную запись.
При потерянной квитанции серверная запись может остаться до TTL: результат создания
может быть неизвестен клиенту. Удаление на сервере и TTL не отзывают уже полученные
параметры WebRTC и не разрывают установленный чат.

Адрес помощника задаётся при запуске через `SSC_CONNECT_URL`, по умолчанию
`http://127.0.0.1:8080`. Для локальной ручной проверки сначала запустите бинарник
`ssc-connect/bin/ssc-connect`, затем два экземпляра desktop как раньше.
Для внешнего сервера задайте HTTPS origin при запуске обоих клиентов. HTTP разрешён
только для loopback. Выбора провайдера в интерфейсе нет; чужие origin, дополнительные
пути, credentials, query и fragment в приглашении отвергаются. Запросы выполняются
в Rust, redirects и proxy из окружения отключены.

Ключ идемпотентности и creator token остаются в памяти Rust-сессии. В интерфейс
передаётся только гостевая ссылка и безопасные состояния/ошибки. Ссылку можно скопировать
в буфер обмена, поэтому её нужно передавать только нужному человеку. Диагностика не
содержит полную ссылку, токены, offer, answer и текст переписки.

Закрытие страницы ради SAS не отменяет обмен; закрытие или замена самой сессии отменяет
ожидание HTTP. После подтверждения обеих сторон создатель делает одну ограниченную
попытку удаления записи; недоступность помощника не мешает дальнейшей переписке.

Для нативной проверки с настоящим сервисом соберите оба проекта и запустите два
`tauri-driver` на портах4444/4445 с одинаковым `SSC_CONNECT_URL`, затем выполните
`node scripts/native-link-smoke.mjs`. Скрипт запускает локальный helper-процесс сам,
проверяет вставку, автоматический answer, SAS, чат при остановленном helper и ошибки
повтора после перезапуска helper. Порт помощника должен быть свободен; тест не
останавливает чужие процессы. Открытие приложения из браузера по клику сюда не входит.
