# Отложенная работа и границы проверки

Обновлено 2026-11-10. Этот список не означает обещания реализовать все пункты.

## Приёмка

- Native macOS microphone packaging/usage descriptions and real-device acceptance are not covered by current Linux/Windows distribution.
- Длительная передача100MiB с shaping/600s credential boundary без dev HMR: быстрый local TURN тест не является production throughput SLA.
- Физический Android/Chrome: вложения, запись голоса, фон/возврат и разные сети.
- Windows GUI: новый чат, произвольные файлы, сохранение и реальные способы захвата окна.
- Разные внешние NAT, Linux/Windows пары, длительные сессии и смена сети.
- Windows TURN TCP/TLS; TURN на443 сейчас не предоставляется.
- Отдельный Swift/iOS-клиент отложен владельцем; Safari на iPhone — другой клиент.

## Повышение уверенности в безопасности

- Внешний независимый аудит композиции протокола, состояния клиентов и границ IPC/WASM.
- Исследование ratcheting/post-compromise recovery. Свежие ключи на чат не означают смену ключей после каждого сообщения.
- Обновление vendor WebRTC/DTLS/TURN при наличии upstream, сохраняющего нужные UDP/TCP/TLS возможности и регрессии.
- Документированные предупреждения GTK и зависимостей отслеживать отдельно от найденных уязвимостей; не подавлять ради зелёного отчёта.

## Принципиальные ограничения

- Сквозное шифрование не защищает от заражённого устройства или копий у собеседника.
- Метаданные сети видны инфраструктуре; прямой WebRTC может раскрывать IP партнёру.
- Очистка приложения не гарантирует стирание swap, снимков ОС, clipboard или остатков памяти.
- Метаданные оригинальных вложений намеренно не удаляются. Выбор файлов средствами ОС может преобразовать оригинал до передачи приложению.
- Web не может универсально запретить внешние screenshots/recording. Ограничение native-окна зависит от ОС и capture API; внешняя камера вне контроля приложения.
- Уведомление об уходе при внезапном завершении процесса best effort; без аутентифицированного уведомления нельзя утверждать, что партнёр намеренно вышел.

## Последующие продуктовые исследования

- Одноразовая передача заранее выбранного файла по ссылке, поверх того же защищённого канала.
- Открытие native-клиента по ссылке ОС без передачи ключей в публичные URL.
- Изменение доменов — при отдельном решении владельца.
